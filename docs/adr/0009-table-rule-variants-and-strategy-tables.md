# 0009. Supported table rules and generated strategy tables

- Status: Accepted
- Date: 2026-10-08

## Context

Players at the Full table level can change table rules. Basic strategy depends on those
rules: dealer hits or stands on soft 17, double after split, surrender, and deck count.
Hand-maintaining a separate full table for every combination would be large and
error-prone. Single- and double-deck games change many cells.

## Decision

- Supported options (`TableOptions`): **4, 6 or 8 decks**, S17/H17, DAS on/off, late
  surrender on/off, and blackjack paying **3:2 or 6:5**. One- and two-deck games are not
  offered, because multi-deck strategy would give wrong hints for them.
- `createRules(options)` builds `GameRules`. The cut card is at 75% penetration
  (`reshuffleCutoffFor`), so even a four-hand split round can never run the shoe dry.
- Strategy tables are generated by `strategyTableFor({ dealerSoft17, doubleAfterSplit,
surrender })`. The S17/DAS base is written as compact row strings, one character per
  dealer upcard (e.g. `"HDDDDHHHHH"`), so each row can be compared with a printed chart at a
  glance. H17 and no-DAS are small override maps on top. Surrender has its own yes/no rows.
- The payout ratio does not change basic strategy, only the money, so it has no table
  variant.

## Consequences

- 8 rule combinations are covered by about 50 lines of data. Tests check that all 8 are
  complete and that S17 vs H17 differ only in the three documented cells.
- A large simulation (`tests/game-core.fairness.test.ts`) confirms the default table plays
  at the published house edge (ADR-0012).
- Adding single-deck support later means adding a deck-count dimension to
  `strategyTableFor`.
